
# Smart Home IoT Backend

Hệ thống quản lý và điều khiển nhà thông minh (Smart Home IoT System) cho phép người dùng giám sát môi trường, điều khiển thiết bị từ xa và thiết lập các kịch bản tự động hóa thông qua giao thức MQTT kết nối với nền tảng Adafruit IO.



## 1. Công nghệ sử dụng (Tech Stack)
* **Framework:** .NET (C#)
* **Kiến trúc:** Clean Architecture (Domain, Application, Infrastructure, API)
* **Database ORM:** Entity Framework Core (Sử dụng cơ chế TPT - Table-Per-Type cho thiết bị)
* **Giao thức IoT:** MQTT (thư viện `MQTTnet`)
* **IoT Platform:** Adafruit IO (Đóng vai trò là MQTT Broker)

## 2. Tính năng cốt lõi (Core Features)
* **Quản lý người dùng:** Đăng ký, đăng nhập (Xác thực bằng JWT) và quản lý thông tin cá nhân.
* **Quản lý không gian (Phòng):** Khởi tạo, chỉnh sửa và tổ chức các phòng trong nhà. Định danh độc nhất bằng `room_id`.
* **Quản lý thiết bị (Devices):** * **Output Devices (Thiết bị đầu ra):** Đèn, quạt, rơ-le... với các trạng thái ON/OFF/AUTO.
  * **Sensors (Cảm biến):** Nhiệt độ, độ ẩm... với khả năng cấu hình ngưỡng an toàn (`threshold_min`, `threshold_max`).
* **Điều khiển thủ công & Giám sát:** Bật/tắt thiết bị theo thời gian thực từ giao diện người dùng, xem biểu đồ dữ liệu môi trường.
* **Hệ thống tự động hóa (Automation):** Tự động kích hoạt thiết bị đầu ra khi dữ liệu cảm biến vượt ngưỡng cài đặt sẵn (VD: Bật quạt khi nhiệt độ > 30°C).
* **Ghi nhận lịch sử (Logging):** Lưu vết toàn bộ hoạt động của hệ thống (do người dùng kích hoạt hoặc do hệ thống tự động) để phục vụ truy xuất và bảo trì.

## 3. Kiến trúc hệ thống (Clean Architecture)

## 4. Thiết kế dữ liệu (Database Schema)

| Thực thể | Thuộc tính chính | Ràng buộc / Quan hệ |
| :--- | :--- | :--- |
| **User** | `Id`, `Email`, `PasswordHash`, `FullName` | `Email` là unique. (1 User - N Rooms) |
| **Room** | `RoomId`, `UserId`, `RoomName` | (1 Room - N Devices) |
| **Device (Base)** | `DeviceId`, `RoomId`, `DeviceName`, `Type`, `FeedKey` | Sử dụng TPT (Table-Per-Type) / Cột `FeedKey` (Unique slug) để giao tiếp Adafruit |
| **OutputDevice** | `Status` (ON, OFF, AUTO) | Kế thừa `Device` |
| **Sensor** | `ThresholdMin`, `ThresholdMax` | Kế thừa `Device` |
| **SensorData** | `Id`, `DeviceId`, `Value`, `Timestamp` | Lưu lịch sử đo (1 Device - N SensorData) |
| **ActionLog** | `Id`, `Timestamp`, `LogType`, `Action`... | `LogType` lưu dạng Manual (Thủ công) hoặc Auto |

## 5. Danh sách API Endpoints

### 🔑 Authentication
* `POST /api/auth/register`: Đăng ký tài khoản mới.
* `POST /api/auth/login`: Đăng nhập, cấp phát token.

### 🏠 Rooms
* `GET /api/rooms`: Lấy danh sách phòng.
* `POST /api/rooms`: Tạo phòng mới.
* `PUT /api/rooms/{roomId}`: Cập nhật thông tin phòng.
* `DELETE /api/rooms/{roomId}`: Xóa phòng.

### 🔌 Devices
* `GET /api/rooms/{roomId}/devices`: Lấy danh sách thiết bị trong phòng.
* `POST /api/rooms/{roomId}/devices`: Thêm thiết bị mới (Đầu ra/Cảm biến).
* `PUT /api/devices/{deviceId}`: Cập nhật thiết bị / cấu hình ngưỡng cảm biến.
* `DELETE /api/devices/{deviceId}`: Xóa thiết bị.

### ⚙️ Control & Monitoring
* `POST /api/devices/{deviceId}/control`: Điều khiển thiết bị (Bật/Tắt). Gọi lệnh MQTT Publish lên Adafruit IO.
* `GET /api/devices/{deviceId}/data`: Lấy chuỗi dữ liệu lịch sử của cảm biến.
* `GET /api/logs`: Lấy lịch sử điều khiển (`ActionLogs`).

## 6. Luồng tích hợp phần cứng (MQTT Data Flow)

* **Thiết bị -> Backend (Sensor Data):** Thiết bị phần cứng đọc dữ liệu -> Publish lên Adafruit Feed -> Backend (MQTT Service) đang Subscribe Feed này sẽ nhận được -> Lưu vào `SensorData` -> Kích hoạt logic tự động hóa (nếu thỏa mãn threshold).
* **Backend -> Thiết bị (Control Command):** Frontend gọi API Control -> Backend cập nhật `ActionLog` & `DeviceState` -> Publish lệnh ("ON"/"OFF") lên Adafruit Feed -> Thiết bị phần cứng Subscribe Feed này nhận lệnh và thực thi rơ-le.
